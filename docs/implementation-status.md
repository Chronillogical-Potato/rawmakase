# Implementation status

The original implementation plan is preserved at the project root. Its crate boundaries are implemented as modules in one Rust package, plus the CLI in `main.rs`, as permitted by the plan. The [code map](code-map.md) describes the current layout; the [architecture guide](architecture.md) explains the domain boundaries and compatibility aliases that replaced the original `core`, `io` and top-level `worker` layout.

- **M0:** native LibRaw bridge, inspect/render/thumbnail/benchmark tools, both sensor paths, scale/headroom tests, float camera-space boundary, explicit WB policy, optional fast path, EXIF strategy and pipeline documentation implemented.
- **M1:** desktop application, background loading/rendering, preview/zoom/pan, exposure/WB, export, versioned sidecars, render generations and history implemented.
- **M2:** light/color/levels/curve controls, hue bands, grading, picker, histogram, clipping overlay, resets and before/after implemented. Familiar controls do not imply Adobe's proprietary rendering behavior.
- **M3:** crop handles, aspect presets, straighten/rotate/flip, folder strip, bounded thumbnails, keyboard navigation, grouped undo/redo, copy/paste, saved presets and session restoration implemented.
- **M4:** basic detail controls, physical-pixel 100% regions, optional display ICC, JPEG/TIFF with sRGB and selected EXIF, immutable single-export jobs, atomic writes and explicit overwrite confirmation implemented.
- **M5:** local fixture integration, 50-open memory test, malformed input/cancellation/future-sidecar/read-only-folder checks, formatting/lint/test commands, dependency documentation and Makefile/desktop packaging implemented. Broader photographic and calibrated-display validation remains a documented limitation.

Deliberate choices: the embedded camera JPEG is the immediate loading preview. Developed previews progress from a draft to full quality, including detail processing in the fit preview; use 100% to assess noise reduction and sharpening. There is one export at a time and navigation waits for it, bounding memory instead of retaining multiple full-resolution photos in a queue. The GPU draws the UI/viewport and now accelerates preview sharpening and resizing through portable wgpu compute. RAW decoding, color processing and exports remain on CPU; unsupported GPU configurations fall back to CPU. See the [preview backend architecture](architecture.md#preview-compute-backend) and [performance record](preview-performance.md).
